# 銷售、購物與體驗的功能

先分清展示、代管結帳或完整商店。沒說只要展示，就把真商務功能列入工作；
不能把購物車動畫當成已完成購物網站。欠商品資料或商務帳號時，先做其他部分並列待補。

## 銷售站

真實聯絡／預約連結最省成本。表單需接收服務、成功／失敗回應、伺服器驗證、節流與
適用同意文字；只在 console 印資料不是完成。未接服務時顯示尚未開放，測試送往指定
測試收件端。真正寄送依使用者授權。

## 購物站的三種範圍

| 範圍 | 交付 | 不能宣稱 |
|---|---|---|
| 展示版 | 商品展示、示範 cart、靜態頁 | 可付款、保留庫存、已成立訂單 |
| 代管結帳 | 自有 SEO 商品頁連到商家設定的正式商品／結帳頁 | 本機 cart 自動同步、交易零費用 |
| 自有商店 | 庫存、訂單、服務端價格、支付整合、通知與退款 | 未測試就可營業 |

代管結帳可作小店完成方案。逐商品付款連結不能假裝多商品 cart 結帳；要一次買多項，
用支援 cart session 的 API 或代管商店原生 cart。

自有商店至少需要：

- 商品獨立 URL、規格／SKU／變體／實際價格與貨幣／庫存，UI 與 JSON-LD 一致。
- cart 加減、刪除、空車與重整；localStorage 只放商品 ID、數量，不放個資或秘密。
- 服務端按受信商品資料重算價格，忽略客戶端金額，驗證數量、庫存、折扣、配送與稅費。
- 支付金鑰僅伺服器使用，優先代管收款頁，不自行收集原始卡號。
- webhook／callback 驗證簽章、時間與金額，處理冪等、重送、次序不同；前端跳到
  success URL 不等於付款。訂單有 pending／paid／failed／cancelled／refunded 狀態。
- 訂單管理、庫存與退款需授權，有權限、資料保留／刪除、備份與還原說明。
- 沙盒實測缺貨、付款失敗、取消、重試、重複回呼與金額竄改；未有具體授權不做真正扣款。

台灣商家選綠界時讀可用 ECPay 技能及官方文件，不能用範例商店 ID／測試金鑰上線。
其他地區按可用支付服務選型，不把綠界當全球預設。
配送、退換貨、隱私與條款依真實營運條件寫草稿；法律義務查所在地官方來源，
不能給所有產業套同一退貨承諾，也不能補假公司、地址或客服。

## 體驗站

開始、操作回應、完成、重玩／返回都要有，支援滑鼠／觸控及鍵盤。隨機內容揭露互動性質，
不宣稱可確定醫療、財務或個人未來。進度若只在瀏覽器儲存要說清楚，清除後可正常重啟。
即時 GPT 解讀另需服務端、金鑰、節流與推論成本，不能把建置時 GPT 產圖文，偷換成
每位訪客無限呼叫 GPT。
