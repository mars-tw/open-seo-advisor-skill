# GPT 圖文素材工作流

使用者要求的圖文由 GPT 生成。網站素材要有真正輸出檔，不能只交 prompt 清單。
模型與參數會變動，API 路徑執行前查 OpenAI 當時文件與帳號支援。

先查宿主實際工具能力。使用者明確要求 GPT 時不暗換模型；只有使用者接受其他生成器
時才採可用替代工具，並如實記錄來源，不能將其他模型圖片標成 GPT。

## 文案與事實分開

GPT 依 brief 寫標題、故事、商品介紹、CTA、FAQ、meta description 與 alt，每頁回答
具體問題。品牌、價格、尺寸、成分、配送、庫存、退貨、評價、證照只能取自已核實資料，
缺少就待補。不要假倒數、假銷量、假見證，也不把模型生成內容當作事實來源。
繁中採台灣用語，關鍵字自然使用。重要標題保留 HTML，不燒進圖片。

## 產圖路由

OpenCode 使用者另見 [工具與安裝說明](opencode.md)：文字模型登入及圖片附件不等於產圖工具。
僅呼叫當前已列出的 MCP／自訂產圖工具，不假設 Codex 的 `image_gen` 或帳號額度可跨工具直接使用。

1. 宿主有 GPT image／imagegen 工具：優先使用，不要求 API key，也不稱無限制免費。
   依實際工具 schema 呼叫，不發明參數；若有 imagegen 技能就讀取其工作流。
2. 宿主沒有工具：交素材 brief、每張 prompt 與可預覽骨架，讓使用者選 ChatGPT 產圖
   後提供檔案，或 OpenAI API。素材仍為待補，不能稱完整成品。
3. 使用者選 API 才使用本機環境變數 `OPENAI_API_KEY`；先核實模型、張數、尺寸及
   估計費用，不能把聊天方案額度說成 API 免費額度。既有 `seo-advisor image` 是獨立
   API／mock 引擎，mock 不是 GPT 圖片；CLI 存在不代表可自動改走付費 API。

官方文件：[Image generation](https://developers.openai.com/api/docs/guides/image-generation)。
本技能不鎖死模型版本；依宿主工具支持的生成、編輯、參考圖與輸出方式工作。

## 素材清單與一致性

先由分鏡的狀態變化列必要素材，再生成。典型為首頁大圖、各幕場景、獨立主角、
前景遮擋、狀態變體、商品情境與社群圖，張數按需求。完整故事不能只產一張首頁圖，
再把不同裁切當成已完成各幕。每張記錄：ID、用途／頁面、比例／尺寸、prompt、參考圖角色、工具與
可知的模型、原圖／網頁檔案、alt、生成與驗收狀態。`pending`／`generated`／`verified`
分開，prompt 寫完不能標 verified。

商品外觀以授權實物參考為準，不增減零件、改規格或偽造認證；純概念商品與虛構場景
在適當位置標示示意。

## 分層與狀態契約

每幕至少說清楚背景、主角與 HTML 內容的關係。需要遮擋、穿越或前後景互動時，才增加
獨立前景／效果層；單純內容圖不硬拆層。為技能的四節拍故事示範列出各幕背景與主角狀態，
一般專案依分鏡決定數量，不規定每次都生四張或固定題材。

| 素材角色 | 產圖時的要求 | 接入時的驗收 |
|---|---|---|
| 場景背景 | 明確地點、視角、光線；留下主角行進路徑與 HTML 文字安全區 | 跨幕有空間或情節關係；主角移動時不會多出背景內另一個同款主角 |
| 主角／商品層 | 固定輪廓、材質、特徵與朝向；需要透明時明確要求透明背景 | 實檔有可用 alpha，沒有棋盤格／白框、裁斷與明顯去背邊緣 |
| 前景遮擋層 | 與背景一致的透視、接觸位置與光線；標明透明區域 | z-order／遮罩正確；主角經過時有可信前後關係，不遮住 CTA |
| 狀態變體 | 寫出改變原因，明確列保留項與新增／移除項 | 主角仍可辨識；變化在分鏡對應時間發生，不意外改商品規格 |
| 靜態替代圖 | 以可讀的一刻表達該幕因果或結果 | 手機、減少動態與無 JS 仍看得懂，無需重播才知道發生什麼 |

同一主角跨幕時建立簡短的「身份卡」：外形比例、辨識特徵、材質、固定色票、
朝向與可變狀態。使用已確認參考圖生成／編輯後續素材；無理由的換形、換色、
光線逆轉或比例漂移要修正。背景不重畫已由獨立圖層承擔的主角，避免合成後出現兩個。

在素材清單增加下列欄位；這是設計契約，不代表 CLI 已支援同名 JSON 欄位：

```text
asset_id／角色：[背景、主角、前景、變體、靜態替代]
章節／使用階段：[進入、轉折、結果，對應 storyboard ID]
連續性：[身份卡 ID；固定項；允許改變與敘事原因]
合成：[透明需求、景深／z-order、錨點、接觸面、裁切安全區]
運動用途：[行進路徑、需要的出血區／留白、被誰遮擋]
替代：[手機裁切；減少動態／無 JS 使用哪張圖與文字]
證據：[生成結果、實檔路徑、瀏覽器各幕截圖、待修內容]
```

```text
用途：網站第 [n] 幕背景／主體／商品情境；[橫向／直向]。
主題：[品牌世界、確切商品與訪客目的]。
構圖：[前景／中景／背景；HTML 文字留白；手機裁切安全區]。
風格：[固定材質、色票、光源、時間與情緒]。
一致性：[跨幕主體／產品外觀／光源的保持項目]。
狀態：[承接哪個場景；目前主角目標；這一幕發生什麼改變]。
圖層：[獨立背景／透明主角／前景；哪些內容不要畫進這張圖]。
運動：[主角路徑與方向；進出畫留白；需要的遮擋與接觸位置]。
參考：[每張輸入圖的角色；編輯目標與不可變部分]。
避免：[文字、浮水印、未授權商標、與實物不符零件]。
```

## 實際生成與接入

1. 先做關鍵場景與主角，打開看身份、構圖、留白、裁切、透明度與商品真實性；確認兩層能合成。
2. 依分鏡產生其餘場景或變體，需要一致性就引用已確認素材，不靠重寫文字碰碰運氣。
3. 原圖保存於專案內；網站用穩定檔案路徑，不引用過期工具 URL，也不只留在工具私有目錄。
4. 按宿主規則處理壓縮／尺寸衍生並保留原圖，支援時採 WebP／AVIF 和 fallback；
   srcset 寬度要符合實檔。不必要就不生成整批 4K。
5. 首屏關鍵圖不要 lazy load，下方圖按需載入，寬高穩定；資訊圖有描述，裝飾 alt 為空。
6. 實際開站逐幕檢查破圖、裁切、文字對比、主角連續、圖層遮擋與操作後果，包含手機、
   倒帶、減少動態與無 JS。單張圖看起來漂亮，只能證明該圖可用；完成合成驗收才標對應場景 verified。

CLI 接圖：圖片放 brief 所在資料夾內，`assets.hero.path` 設相對路徑，`alt` 為描述，
`source` 為 `gpt-image`，重建至新目錄。CLI 不替標籤證明圖片來源，要另存工具證據與 prompt。
主圖欄位只完成入口素材。多幕故事依目前版本的 brief schema 接入場景／主角資產；
先讀 schema 與範例，不把上述設計契約當成程式接受的欄位。若 CLI 不足，agent 應沿用
專案技術棧完成分層與時間軸，不能以單張 zoom 當成故事完成。

CLI 接受 PNG／JPEG／WebP／AVIF 的單張靜態圖，15 MB 及 2,500 萬像素以內。
Pillow 必須能解碼該格式，AVIF 依安裝環境的 decoder 支援；建置與檢查都驗證容器及像素，
不只看副檔名或簽章。動畫圖先按宿主工具規則匯出靜態影格。
