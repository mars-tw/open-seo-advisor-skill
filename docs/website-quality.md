# 驗收與交接

按實際站型跑適用項目。文件存在或看起來合理不能代替執行證據。

## 三種狀態

- **可預覽骨架**：能開，但素材／內容／商務待補，預設 noindex。
- **已驗收成品**：使用者要求的範圍完成且有測試證據，可審查發布。
- **已部署且驗證**：發布後讀回正式網址、HTTPS、資源與功能，記錄時間及回滾點。

「已驗收成品」僅表示本次約定的網站與測試完成。SEO 收錄、非品牌流量及回答引擎引用
要上線後另行觀察，不能由交付網站推定。茶屋與工筆兩個公開網址是單頁互動示範；
只有動畫可預覽，不代表它們是已驗證的 SEO／AEO 成效案例。

所有 preview／staging 預設不收錄，即使內容已驗收也保留 noindex；必要時加存取驗證。
其網域、canonical、支付金鑰、webhook 與通知收件端和 production 分開，測試站使用沙盒。
只有切換已授權的正式環境時，才解除對應收錄限制並啟用已驗證的正式設定。

CLI `website check` 是生成器的有限離線檔案／技術檢查；`baseline_ready` 不等於後兩者。
exit 0＝基線完整、2＝scaffold 待補、1＝invalid，讀 JSON 缺口，不把所有結果都叫通過。

## 內容與搜尋

- 核心 URL 回傳適當狀態，原始 HTML 有各頁內容和可追蹤內部 anchor。
- 重要頁逐頁核對獨特、準確的 title 與 meta description；主標與 H2／H3 描述實際章節，
  讓人與輔助技術容易導覽，不以 H2 數量或固定跳級規則判定 Google 排名成敗。
- title／description／canonical 與內容相符；正式 robots／meta／sitemap 一致，
  沒誤留 noindex；預覽不搶 canonical；404 真回 404。
- structured data 可解析且符合可見事實，Product／Offer 不放未核實售價與庫存。
- 沒過期資料、假來源、假評分，不把 GPT 示意圖當實景證據，主要問題有直接答案。
- 圖片及相對路徑有效，不指向工具臨時連結；內部文件與憑證不在公開輸出。
- 多種商品、分類、服務或政策若需要個別搜尋與分享，使用可直接開啟的 URL；
  同頁 `#hash` 不計為另一頁。單頁只服務單一目的時不強制拆頁。

逐頁驗收至少記錄：URL、對應訪客問題、HTTP、title、meta description、主標與主要章節、
canonical、重要內部入口、LCP 元素與量測環境、索引狀態及未完成項。檢查不能執行
就寫「未驗證」，不能因 `website check` 回傳 `baseline_ready` 省略。對於要宣稱
SEO／AEO 成效的站，另需上線後 Search Console 的非品牌查詢曝光與點擊；要宣稱
詢問或銷售改善時才補相應轉換證據。
品牌名查詢分開列，回答引擎引用只記時間、題目和 URL 的樣本。

## 體驗

- 手機／桌面逐幕查看目標、阻力、操作後果與解決，無水平溢出、遮擋與破圖。
- 主角跨幕可辨識，進出方向、物件、前後景與光線有合理交接；不只是一張圖放大。
- 每幕入場、轉折和結果符合分鏡；不同背景也須有因果連結，主角不能無故消失或瞬移。
- 互動帶來可見且持續到相關下一幕的後果；結果文案和畫面一致。未操作、略過與重玩都有合理狀態。
- 自然上下捲動、章節跳轉、快速捲到終點與略過故事，仍可重建正確場景和 CTA。
- 另須真正捲到頁面最底部，檢查固定舞台在段落結束時退出，後續說明與頁尾沒有被覆蓋；
  只跳到最後一幕不算底部驗收。桌面、手機與靜態閱讀都要檢查，並保留段落交界的畫面或元素邊界數值。
- 鍵盤可操作及離開所有元件，焦點可見，dialog 能關閉且焦點返回，錯誤有文字。
- 系統減少動態、頁面開關、無 JS 三種情況可讀內容與主要導航。
- 表單／cart／體驗有真實空白、失敗、成功與重試狀態。
- console 無未處理錯誤，資源無 404，圖片與字體不造成明顯跳動。

## 故事的瀏覽器證據

要求沉浸式故事時，`website check` 的結構檢查不能替代敘事驗收。技能的完整故事示範
至少覆蓋四個因果節拍；一般專案依已確認分鏡驗證全部必要節拍，不強加固定幕數或題材。

先把瀏覽器操作與預期畫面列在 `storyboard.md`，再保存實際截圖或錄影索引。每幕至少
保留入場、主要轉折和結果的畫面；相鄰幕共用的邊界可共用一張證據，不為湊張數重拍。

| 檢查情境 | 必須留的證據 | 判定重點 |
|---|---|---|
| 桌面順捲 | 各幕階段截圖，記錄 viewport、章節 ID 與相對進度 | 狀態確實改變；主角、阻力、後果與結果看得懂 |
| 操作與分支 | 操作前、操作後與相關下一幕 | 不只按鈕變色；路徑／物件／結果依選擇改變 |
| 倒帶與重進 | 從結果倒回先前轉折，再向下回結果的截圖 | 沒有殘留圖層、重複主角、錯誤文字或過期狀態 |
| 跳章與略過 | 從入口直接到中段、終幕與 CTA | 不需要先跑前一幕才能正確顯示；主要任務可完成 |
| 手機 | 約 390px 寬下全部必要節拍與操作結果 | 裁切仍看見主角／後果，沒有 sticky 遮字、橫溢或觸控障礙 |
| 減少動態 | 系統減少動態與頁面開關各測一次，保存故事及結果 | 停止連續運動；靜態圖和文字保留因果，章節連結可用 |
| 無 JavaScript | 重新載入後的各幕內容、圖片及主要連結 | 說明與預設路徑完整；依賴 JS 的選項有可理解替代 |

同一進度重現時的使用者選擇、動態開關與 viewport 應相同，才可比較倒帶前後。
記錄實際看見的結果，不能由 CSS、資料欄位或預期推定畫面通過。截圖只能證明該時刻，
連續動作的穿透、跳接、閃爍與遮擋另以實際捲動或錄影檢查；未看過就標未驗證。

驗收紀錄的最小格式：

```text
章節／案例：[ID 與分支]
條件：[瀏覽器、viewport、動態設定、JS 狀態、日期、程式版本]
操作：[從哪裡開始、捲到哪個進度、按什麼、是否倒帶]
預期：[可見的主角／場景／後果與文字]
實際：[觀察結果]
證據：[截圖／錄影檔案與定位]
結論：[通過／待修／未驗證；缺口與修復後複驗]
```

一旦故事只剩換背景、縮放或標語，回到分鏡補齊狀態與因果後再驗收，不以「有動畫」
抵銷此缺口。若使用者本來只要簡單動效頁，按該範圍完成即可，交付時不要稱完整互動故事。

## 效能、主機與商務

記錄工具、裝置／viewport、日期與條件；首屏特別核對實際 LCP 元素是否被延後發現、
錯誤套用 lazy loading 或被大量場景圖競爭頻寬。良好 LCP 參考實際使用者手機與桌面
各自第 75 百分位 ≤ 2.5 秒。Lighthouse 是實驗室結果，現場 CWV 無資料就標 N/A。
「60 FPS」「無掉幀」等結論需要實際 performance trace 或同等量測、測試裝置與測試區間；
順利截到幾張圖不能證明幀率。未量測時只回報已實際檢查的操作、載入與視覺結果。
圖片與 JS 超出目標裝置負擔時先壓縮或簡化故事；發布只包含公開輸出。
依 [託管文件](website-hosting.md) 重查方案／額度／billing／region，不能保證絕不超額。
按 [商務文件](website-commerce.md) 跑對應測試；無正式帳號就列未驗收，不寫可收款。

## 交付

發布前完成程式、素材、預覽、測試與目標設定；已有具體授權就執行，沒有才在這時確認
成品、帳號／網域及成本邊界。不要先為未知成品索取批准。

`launch-report.md` 記錄：狀態與範圍、預覽／已驗證正式 URL、原始碼、素材與來源、
分鏡與素材對照、各幕／倒帶／手機／替代模式證據、實測指令／操作及結果、商務完成程度、
部署版本／額度／回滾、sitemap／robots／canonical、
後續更新方法與待補資料。Search Console 提交不等於已索引。
收尾用簡短結果與可開連結，不讓使用者先讀長報告才能看網站。
